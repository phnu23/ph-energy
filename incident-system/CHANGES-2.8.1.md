# ระบบรายงานอุบัติการณ์ — รุ่น 2.8.1 (ต่อจาก 2.8.0)

## สิ่งที่เปลี่ยน
1. **คณะ/กองกรอกชั่วโมงการทำงานเองได้ (เหมือน 2.6.6)**
   หัวหน้าสำนักงานเลขานุการ รองคณบดี (กำกับดูแล) คณบดี/ผู้อำนวยการกอง และผู้ดูแลระดับคณะ
   กรอกจำนวนบุคลากรและชั่วโมงทำงาน/คน/ปีของคณะตนเองได้ที่ Dashboard รายงานภาพรวม →
   การ์ดดัชนีความปลอดภัย → "ทะเบียนจำนวนบุคลากรและชั่วโมงการทำงาน" (แก้คณะอื่นไม่ได้)
   ค่ายังเก็บในชีต OrgHeadcount กลาง ทุกคนเห็นดัชนีตรงกัน และมีคอลัมน์รวมชั่วโมง/ปีคำนวณให้ทันที
2. **ผู้บริหารเห็น Dashboard รายงานภาพรวมเต็มรูปแบบ**
   รองอธิการบดี รองอธิการบดี (กำกับดูแล) อธิการบดี และบทบาทใหม่ `assistant_president` (ผู้ช่วยอธิการบดี)
   เห็นรายงานภาพรวมทุกระดับทั้งมหาวิทยาลัย (ยกเลิกการจำกัดเฉพาะระดับ 3 ขึ้นไป)
   คณบดีเห็นรายงานภาพรวมของคณะตนเองเหมือนเดิม
   ทุกบทบาทข้างต้นยังเป็นผู้กำกับดูแล จึงไม่เปิดรายละเอียดรายเรื่องและไม่แก้ไขข้อมูล
3. **กราฟเปรียบเทียบดัชนีความปลอดภัยรายคณะ (IFR / ISR / PDFR)**
   ดูได้ทั้งรายเดือนและรายปี (ปีงบประมาณ ต.ค.–ก.ย. หรือปีปฏิทิน) พร้อมเส้นค่ารวมมหาวิทยาลัยและตารางข้อมูล
   คำสั่ง API ใหม่ `report.facultyIndex` คืนเฉพาะตัวเลขรวมรายคณะรายเดือน
   เห็นได้โดยคณบดี กองอาคารสถานที่ รองอธิการบดี ผู้ช่วยอธิการบดี อธิการบดี และผู้ดูแลระบบ

## วิธีอัปเดต
1. วาง `Code.gs`, `Api.gs`, `Index.html`, `Tests.gs` ทับไฟล์เดิมใน Apps Script (`appsscript.json` ไม่เปลี่ยน)
2. รัน `runUnitTests` จาก Editor ให้ผ่านทั้งหมด
3. ถ้าจะใช้บทบาทผู้ช่วยอธิการบดี ให้รัน `setupUsersDropdownsFromEditor` อีกครั้งเพื่อเพิ่ม `assistant_president` ใน dropdown
   แล้วกำหนดบทบาทนี้ให้ผู้ใช้ในทะเบียนผู้ใช้
4. Deploy → Manage deployments → Edit → New version → Deploy (ใช้ URL เดิม)

# รุ่น 2.8.2

1. **ชั่วโมงการทำงานมาตรฐานเป็น 7 ชั่วโมง/วัน**
   ค่ามาตรฐาน = `CONFIG.HOURS_PER_DAY` (7) × `CONFIG.WORK_DAYS_PER_YEAR` (240) = **1,680 ชม./คน/ปี** (เดิม 1,920)
   หน่วยงานที่เว้นช่องชั่วโมง/คน/ปีไว้จะเปลี่ยนเป็นค่าใหม่ทันที ส่วนหน่วยงานที่เคยกรอกตัวเลขเอง (เช่น 1,920) ยังใช้ค่าเดิม
   ถ้าต้องการใช้ 7 ชั่วโมงด้วย ให้ลบค่านั้นออกหรือกรอกค่าใหม่
2. **วิธีคำนวณและตัวอย่างสำหรับบุคลากรหลายรูปแบบ** ในทะเบียนบุคลากร (เต็มเวลา เข้าเวร พาร์ตไทม์ ผู้ช่วยวิจัย)
   พร้อมตัวช่วยคำนวณค่าเฉลี่ยถ่วงน้ำหนัก เช่น
   40 คน × 7 × 240 = 67,200 · 10 คน × 8 × 250 = 20,000 · 6 คน × 4 × 240 = 5,760
   รวม 56 คน 92,960 ชม. → 92,960 ÷ 56 = 1,660 ชม./คน/ปี แล้วกด "ใส่ค่าลงทะเบียน"
3. **กราฟเปรียบเทียบดัชนีแยกคลัสเตอร์** เลือกได้ 3 แบบ
   - ทุกคลัสเตอร์ (แยกกลุ่ม): คณะเรียงอยู่ใต้หัวคลัสเตอร์ แต่ละหัวแสดงค่ารวมของคลัสเตอร์
   - เปรียบเทียบระหว่างคลัสเตอร์: หนึ่งแท่งต่อคลัสเตอร์ คำนวณจากผลรวมของหน่วยงานในคลัสเตอร์
   - เลือกคลัสเตอร์เดียว: ดูเฉพาะคณะในกลุ่มนั้น
   คลัสเตอร์ใช้กลุ่มเดียวกับผังหน่วยงาน (ORG) ใน Index.html

# รุ่น 2.8.3

**แต่ละคณะ/กองกรอกวิธีคิดเวลาการทำงานของตนเอง** (ทะเบียนบุคลากร → "วิธีคิดเวลาการทำงานของหน่วยงาน")
- กรอกเป็นกลุ่มบุคลากร: ชื่อกลุ่ม · จำนวนคน · ชั่วโมง/วัน · วันทำงาน/ปี (เพิ่ม/ลบกลุ่มได้ สูงสุด 20 กลุ่ม)
- ระบบคำนวณจำนวนบุคลากร = Σ คน และชั่วโมง/คน/ปี = Σ(คน × ชม. × วัน) ÷ Σ คน ให้เองทั้งหน้าจอและเซิร์ฟเวอร์
- วิธีคิดถูกบันทึกในคอลัมน์ใหม่ `staffGroups` ของชีต OrgHeadcount (ระบบเพิ่มคอลัมน์ให้อัตโนมัติ ไม่กระทบข้อมูลเดิม)
- หน่วยงานที่ใช้วิธีคิด ช่องจำนวนคน/ชั่วโมงในตารางจะล็อกไว้ ต้องแก้ที่วิธีคิด หรือกด "ล้างวิธีคิด" เพื่อกลับไปกรอกตัวเลขเอง
- ผู้บริหารที่ดูได้แต่แก้ไม่ได้ เห็น "ที่มาของชั่วโมงการทำงานแต่ละหน่วยงาน" ว่าแต่ละหน่วยงานคิดอย่างไร
- หน่วยงานที่ไม่กรอกเลย ยังใช้ค่ามาตรฐาน 7 ชม. × 240 วัน = 1,680 ชม./คน/ปี

# รุ่น 2.8.5 — ผังคลัสเตอร์ใหม่

| คลัสเตอร์ | หน่วยงาน |
|---|---|
| กลุ่มวิทยาศาสตร์สุขภาพ | 7 คณะ |
| กลุ่มวิทยาศาสตร์และเทคโนโลยี | 7 คณะ/วิทยาลัย |
| กลุ่มมนุษยศาสตร์และสังคมศาสตร์ | 7 คณะ/วิทยาลัย |
| สำนักงานอธิการบดี มหาวิทยาลัยนเรศวร | 19 กอง/หน่วยงาน (เพิ่ม สำนักงานอธิการบดี, สำนักงานตรวจสอบภายใน) |
| หน่วยงานอื่นๆ | สำนักหอสมุด, สำนักงานสภามหาวิทยาลัย (ใหม่) |
| โรงเรียน | 2 โรงเรียน |

ชื่อที่เปลี่ยน — ข้อมูลเดิมที่ใช้ชื่อเก่ายังนับเป็นหน่วยงานเดียวกันอัตโนมัติ (UNIT_ALIASES ใน Code.gs และ Index.html):
- ~~กองกลาง สำนักงานอธิการบดี → กองกลาง~~ (ยกเลิกในรุ่น 2.8.10 — ดูด้านล่าง)
- สำนักงานหอสมุด → สำนักหอสมุด
- โรงเรียนอนุบาลและประถมสาธิตมหาวิทยาลัยนเรศวร → โรงเรียนอนุบาลและประถมสาธิต มหาวิทยาลัยนเรศวร

ถอดออกจากผัง: สถานภูมิภาคเทคโนโลยีอวกาศและภูมิสารสนเทศ ภาคเหนือตอนล่าง, หน่วยงานอื่น ๆ
(ข้อมูลเดิมของสองหน่วยงานนี้ยังอยู่ แต่จะแสดงในกลุ่ม "หน่วยงานอื่นนอกผังหน่วยงาน" ของกราฟเปรียบเทียบ)

หลังอัปเดต: แก้คอลัมน์ A ของแท็บ "หน่วยงาน" ในทะเบียนผู้ใช้ให้ตรงกับรายชื่อใหม่ (dropdown ในชีต)
และใช้หน้า "ตรวจความพร้อมทะเบียนผู้ใช้" ดูผู้ใช้ที่ยังใช้ชื่อเก่า (ขึ้นเป็นคำเตือน)

# รุ่น 2.8.7 — ตรวจทานก่อนขึ้นระบบจริง

## บั๊กที่พบและแก้แล้ว
1. **ฟอร์มเขียนรายงานแสดงหน่วยงานผิด** — ผู้ใช้ที่ทะเบียนยังเป็นชื่อเดิม (เช่น "สำนักงานหอสมุด") หรือหน่วยงานที่ถอดออกจากผัง
   dropdown จะตกไปที่ "คณะเภสัชศาสตร์" (แก้ไขในรุ่น 2.8.9: ตรวจซ้ำแล้วพบว่าเซิร์ฟเวอร์บันทึกหน่วยงานจากทะเบียนผู้ใช้ ไม่ได้ใช้ค่าในช่องนี้ ข้อมูลจึงไม่เคยบันทึกผิด แต่หน้าจอและหน้ายืนยันแสดงผิด) → แก้ให้เลือกชื่อใหม่ให้อัตโนมัติ และแสดงหน่วยงานนอกผังเป็นตัวเลือกแยก
2. **หน้าจัดการผู้ใช้** มีปัญหาเดียวกัน — กดบันทึกแถวผู้ใช้ที่อยู่หน่วยงานนอกผัง จะย้ายเขาไปคณะเภสัชศาสตร์เงียบ ๆ → แก้แล้ว
3. **ตรวจว่าคณะมีรองคณบดี (กำกับดูแล) หรือไม่** เทียบชื่อหน่วยงานแบบตรงตัว คณะที่ใช้ชื่อเดิมจะถูกมองว่าไม่มี
   หน้าจอจะเปิดปุ่มให้คณบดีตรวจสอบแทน แล้วเซิร์ฟเวอร์ปฏิเสธ → แก้ให้เทียบผ่านตารางชื่อเดิม/ชื่อใหม่
4. **หน้าตรวจความพร้อมทะเบียนผู้ใช้** แยกหน่วยงานชื่อเดิมกับชื่อใหม่เป็นสองรายการ ทำให้ฟ้องว่าขาดบทบาททั้งที่มีครบ → แก้แล้ว
5. กราฟเปรียบเทียบไม่ไฮไลต์ "คณะของท่าน" ให้ผู้ใช้ที่ทะเบียนเป็นชื่อเดิม → แก้แล้ว
6. วิธีคิดเวลาการทำงานรับจำนวนคนรวมได้ถึง 2 ล้านคน (20 กลุ่ม × 100,000) → จำกัดรวมไม่เกิน 100,000 ตามเพดานเดิม
7. เดือนปัจจุบันในกราฟเปรียบเทียบใช้เวลา UTC ช่วง 00:00–06:59 ของวันที่ 1 จะยังนับเป็นเดือนก่อน → ใช้เวลาไทย

# รุ่น 2.8.8 — ผู้มีสิทธิ์กรอกวิธีคิดเวลาการทำงาน

| บทบาท | กรอก/บันทึกจำนวนบุคลากรและวิธีคิดเวลาการทำงาน |
|---|---|
| หัวหน้าสำนักงานเลขานุการ/ผู้ได้รับมอบหมาย | ✅ เฉพาะคณะ/กองของตนเอง |
| รองคณบดี (กำกับดูแล) | ✅ เฉพาะคณะ/กองของตนเอง |
| ผู้ดูแลระบบ | ✅ ทุกคณะ (สำรองกรณีหน่วยงานยังไม่มีสองบทบาทข้างต้น) |
| คณบดี/ผอ.กอง, ผู้ดูแลระดับคณะ | ดูได้ (ที่มาของชั่วโมงการทำงาน) แก้ไม่ได้ — เปลี่ยนจากรุ่น 2.8.1–2.8.7 |
| บทบาทอื่น | ดูได้ตามขอบเขต แก้ไม่ได้ |

ข้อควรเตรียม: หน่วยงานที่ยังไม่มีผู้ใช้บทบาทหัวหน้าสำนักงานฯ หรือรองคณบดี (กำกับดูแล) จะไม่มีใครในหน่วยงานกรอกได้
ตรวจได้ที่หน้า "ตรวจความพร้อมทะเบียนผู้ใช้" (ฟ้องหน่วยงานที่ขาดหัวหน้าสำนักงานฯ อยู่แล้ว) หรือให้ผู้ดูแลระบบกรอกแทน

# รุ่น 2.8.9 — ตรวจทานรอบสุดท้าย

## บั๊กที่พบและแก้แล้ว
1. **ปุ่มรีเฟรช (↻) ไม่โหลดกราฟเปรียบเทียบรายคณะใหม่** — ตัวเลขค้างค่าเดิมจนกว่าจะโหลดหน้าเว็บใหม่ทั้งหน้า
   → กดรีเฟรชเองจะโหลดทั้งกราฟเปรียบเทียบและทะเบียนบุคลากรใหม่ (ถ้ามีค่าที่พิมพ์ค้างยังไม่บันทึก จะไม่โหลดทะเบียนทับ)
2. **รีเฟรชอัตโนมัติทุก 3 นาทีวาดหน้ารายงานใหม่ระหว่างกำลังกรอกทะเบียน** ช่องที่พิมพ์อยู่หลุดโฟกัส
   → รีเฟรชอัตโนมัติจะข้ามการวาดหน้ารายงานใหม่ ขณะผู้ใช้กำลังกรอกหรือมีค่าที่ยังไม่บันทึก
3. **ออกจากระบบแล้วข้อมูลรายงานของผู้ใช้คนก่อนยังค้างในแท็บ** ผู้ใช้คนถัดไปที่เข้าระบบในแท็บเดียวกันอาจเห็นทะเบียนบุคลากร
   และตัวเลขเปรียบเทียบตามขอบเขตของคนก่อน → ล้างทั้งหมดเมื่อออกจากระบบ

## ผลการตรวจรอบสุดท้าย
- ชุดทดสอบหน่วย 87/87 ผ่าน
- ตารางบทบาท ROLES, UNIT_ALIASES, FACULTY_ADMIN_ASSIGNABLE ฝั่งหน้าจอกับเซิร์ฟเวอร์ตรงกันทุกค่า (14 บทบาท)
- สิทธิ์บันทึกทะเบียน: เฉพาะหัวหน้าสำนักงานฯ รองคณบดี (กำกับดูแล) และผู้ดูแลระบบ อีก 11 บทบาทถูกปฏิเสธ
- กราฟเปรียบเทียบ: เห็นเฉพาะคณบดี กองอาคารสถานที่ รองอธิการบดี ผู้ช่วยอธิการบดี รองอธิการบดี (กำกับดูแล) อธิการบดี ผู้ดูแลระบบ
- เปิดทุกหน้าของทั้ง 14 บทบาท ไม่มี JavaScript error
- ขั้นตอนกรอกวิธีคิดเวลาการทำงานครบวงจร ทดสอบในบทบาทหัวหน้าสำนักงานฯ และรองคณบดี (กำกับดูแล)
- รีเฟรชเอง / รีเฟรชอัตโนมัติขณะกรอก / ออกจากระบบ ทำงานถูกต้อง

## ความเสี่ยงที่ยังเหลือ (ไม่ใช่บั๊ก แต่ควรรู้ก่อนเปิดใช้)
- ยังไม่ได้ทดสอบกับ Google Sheets/Drive และการเข้าสู่ระบบจริง — ต้องทำตาม "ลำดับขึ้นระบบจริง" ข้อ 3 และ 7
- คณบดีเห็นตัวเลขรวมรายเดือนของคณะอื่นในกราฟเปรียบเทียบ (ไม่มีรายละเอียดรายเรื่อง) — ตามที่ออกแบบไว้
- รองอธิการบดี/ผู้ช่วยอธิการบดี ได้รับข้อมูลรายเรื่องทุกระดับเหมือนอธิการบดี (เดิมจำกัดระดับ 3 ขึ้นไป) — ตามที่ขอในรุ่น 2.8.1
- กองที่ไม่มีผู้ใช้บทบาทหัวหน้าสำนักงานฯ/รองคณบดี (กำกับดูแล) จะกรอกทะเบียนเองไม่ได้ ต้องให้ผู้ดูแลระบบกรอกแทนหรือแต่งตั้งบทบาท
- หน่วยงานที่เคยกรอกชั่วโมง/คน/ปีเป็นตัวเลขเอง (เช่น 1,920) ไม่เปลี่ยนเป็น 1,680 อัตโนมัติ

# รุ่น 2.8.10 — กองกลาง และ สำนักงานอธิการบดี เป็นสองหน่วยงานแยกกัน

กองกลาง และ สำนักงานอธิการบดี (คลัสเตอร์ "สำนักงานอธิการบดี มหาวิทยาลัยนเรศวร") มีผู้อำนวยการของตนเอง
ระบบแยกเป็นสองหน่วยงานโดยสมบูรณ์ ตรวจแล้ว:
- ผอ.กองกลาง เห็นเฉพาะรายงานของกองกลาง / ผอ.สำนักงานอธิการบดี เห็นเฉพาะของสำนักงานอธิการบดี
  (ทั้งคู่ยังเห็นเหตุระดับ 3 ขึ้นไปของหน่วยงานอื่นในภาพรวม ตามสิทธิ์คณบดี/ผอ.กอง เดิม)
- ทะเบียนบุคลากรและวิธีคิดเวลาการทำงานแยกแถวกัน หัวหน้าสำนักงานฯ ของหน่วยหนึ่งแก้ของอีกหน่วยไม่ได้
- กราฟเปรียบเทียบแสดงเป็นสองแท่งในคลัสเตอร์เดียวกัน

**การตั้งค่าผู้ใช้:** ผู้อำนวยการแต่ละหน่วย ใช้บทบาท `dean` (คณบดี / ผู้อำนวยการกอง) และเลือกหน่วยงานของตนเอง
หัวหน้าสำนักงานฯ/ผู้ได้รับมอบหมาย ของแต่ละหน่วย ใช้บทบาท `office_head` แยกกันหน่วยละคน

**แก้จากรุ่น 2.8.5:** ชื่อเดิม "กองกลาง สำนักงานอธิการบดี" ไม่ถูกรวมเข้ากองกลางอัตโนมัติอีกต่อไป
เพราะผังเดิมไม่มีหน่วย "สำนักงานอธิการบดี" บุคลากรของทั้งสองหน่วยจึงอาจลงทะเบียนด้วยชื่อนี้
ถ้ารวมอัตโนมัติ ผอ.กองกลาง จะเห็นรายงาน (รวมเรื่องอ่อนไหว) ของสำนักงานอธิการบดี
ตอนนี้ชื่อเดิมยังเป็นหน่วยงานแยกเหมือนก่อนรุ่น 2.8.5 (ไม่มีใครเห็นข้อมูลเพิ่ม ไม่มีข้อมูลหาย)

**สิ่งที่ผู้ดูแลต้องทำ (ก่อนหรือหลังขึ้นระบบไม่นาน):**
1. เปิด "ตรวจความพร้อมทะเบียนผู้ใช้" — ผู้ใช้ที่ยังใช้ชื่อเดิมขึ้นเป็นข้อผิดพลาดสีแดง พร้อมข้อความให้เลือกหน่วยงาน
2. แก้ผู้ใช้แต่ละคนเป็น "กองกลาง" หรือ "สำนักงานอธิการบดี" ในหน้าจัดการผู้ใช้
3. ในชีต Incidents กรองคอลัมน์ faculty = "กองกลาง สำนักงานอธิการบดี" แล้วแก้คอลัมน์ faculty และ unit ของแต่ละเรื่องให้ตรงหน่วยงานจริง
   (หน้าเว็บแก้หน่วยงานของรายงานไม่ได้ ต้องแก้ในชีต) — ถ้ายังไม่แก้ เรื่องเหล่านี้จะไม่อยู่ในขอบเขตของ ผอ. ทั้งสองหน่วย
4. ในชีต OrgHeadcount ถ้ามีแถว "กองกลาง สำนักงานอธิการบดี" ให้ลบ แล้วให้แต่ละหน่วยกรอกใหม่

# รุ่น 2.8.11 — สิทธิ์ผู้บริหารเปิดดูรายละเอียดอุบัติการณ์ระดับ 3 ขึ้นไป

**ผลตรวจก่อนแก้ (รุ่น 2.8.10 และ 2.8.0 เดิม)**
- อธิการบดี รองอธิการบดี (ทั้งสองแบบ) ผู้ช่วยอธิการบดี เปิดรายละเอียดไม่ได้เลยทุกระดับ (เซิร์ฟเวอร์ปฏิเสธ หน้าจอซ่อนเมนู)
  ทั้งที่อีเมลแจ้งเหตุระดับ 3 ขึ้นไปบอกให้ "เปิดระบบ"
- **ช่องโหว่:** เบราว์เซอร์ของบทบาทเหล่านี้ได้รับเนื้อหาครบทุกเรื่องทุกระดับ (ชื่อเรื่อง เนื้อหา ผู้รายงาน รวมเรื่องอ่อนไหว)
  หน้าจอแค่ไม่แสดง แต่อ่านได้จากเครื่องมือนักพัฒนาของเบราว์เซอร์

**หลังแก้**
| | ระดับ 3–5 | ระดับ 1–2 |
|---|---|---|
| อธิการบดี / รองอธิการบดี (กำกับดูแล) / รองอธิการบดี / ผู้ช่วยอธิการบดี | เปิดรายละเอียดได้ (อ่านอย่างเดียว) รวมเรื่องอ่อนไหว | เห็นเฉพาะในสถิติ เบราว์เซอร์ได้รับแค่ตัวเลข/หมวด ไม่มีเนื้อหา |
- เมนูใหม่ "รายงานอุบัติการณ์ระดับ 3 ขึ้นไป" และ "ค้นหาย้อนหลัง" (แสดงเฉพาะระดับ 3 ขึ้นไป)
- ไม่มีปุ่มดำเนินการใด ๆ (ทุกคำสั่งแก้ไขตรวจสิทธิ์รายคำสั่งที่เซิร์ฟเวอร์ ผู้บริหารไม่มีสิทธิ์เหล่านั้น)
- แดชบอร์ด รายงานภาพรวม และดัชนีความปลอดภัย ยังนับครบทุกระดับเหมือนเดิม
- เรื่องที่ผู้บริหารเป็นผู้รายงานเอง ยังเห็นครบทุกระดับ
- ระดับที่ใช้ตัดสิน = ระดับที่ประเมินแล้ว ถ้ายังไม่ประเมินใช้ระดับที่ระบบเสนอ
- บทบาทกำกับดูแลอื่น (รองคณบดี, คปอ.) ไม่เปลี่ยนแปลง

**ข้อจำกัดที่ยังมี:** ไฟล์แนบ (รูป/เอกสารใน Google Drive) ของเรื่องระดับ 3 ขึ้นไป ผู้บริหารยังเปิดไม่ได้
เพราะสิทธิ์ไฟล์แนบจำกัดที่ผู้ปฏิบัติในคณะ (ATTACH_VIEW_ROLES) หน้ารายละเอียดจะเห็นชื่อไฟล์แต่เปิดไฟล์ไม่ได้

# รุ่น 2.8.12 — อีเมลแจ้งเตือนถึงรองอธิการบดี (กำกับดูแล) และอธิการบดี

**ผู้รับอีเมล (ตามตารางระดับความรุนแรง)**
| ระดับ | รองอธิการบดี (กำกับดูแล) | อธิการบดี | กองอาคารสถานที่ | คณะที่เกิดเหตุ* |
|---|---|---|---|---|
| 1–2 | – | – | – | – |
| 3 | ✅ | – (เดิมได้) | ✅ | ✅ |
| 4–5 | ✅ | ✅ | ✅ | ✅ |
\* หัวหน้างานของหน่วยงานที่เกิดเหตุ, หัวหน้าสำนักงานฯ, รองคณบดี (กำกับดูแล), รองคณบดี, คณบดี/ผอ.กอง, คปอ.
รองอธิการบดี (ทั่วไป) และผู้ช่วยอธิการบดี ไม่ได้รับอีเมล (เปิดดูในระบบได้)

**สิ่งที่แก้**
1. อธิการบดีได้อีเมลเหตุระดับ 3 ขัดกับตารางและข้อความในอีเมลเอง → รับเฉพาะระดับ 4–5
2. **อีเมลซ้ำ**: เหตุที่ระบบเสนอระดับ 3 ขึ้นไปส่งอีเมลตอนสร้าง แล้วส่งซ้ำอีกครั้งตอนประเมินแม้ระดับเท่าเดิม
   → ตอนประเมินส่งเฉพาะเมื่อระดับสูงกว่าที่เสนอ (เช่น 2→3 หรือ 3→4 ซึ่งอธิการบดีจะได้รับเป็นครั้งแรก)
3. **ข้อมูลอ่อนไหวรั่วทางอีเมล**: เรื่องคุกคาม/ภาวะวิกฤต ปิดชื่อเรื่องแล้วแต่ยังส่งสถานที่และพิกัดแผนที่ (เช่น ห้องพัก) → ปิดด้วย
4. **ลิงก์ตรงไปที่เรื่อง**: อีเมลมีลิงก์ `…/exec?incident=IR-…` เข้าสู่ระบบแล้วเปิดหน้ารายละเอียดเรื่องนั้นทันที
   (ผู้บริหารเปิดได้เพราะเป็นระดับ 3 ขึ้นไป · ถ้าไม่มีสิทธิ์จะขึ้นข้อความแจ้ง)
5. **ตรวจย้อนหลังได้**: ทุกการส่งบันทึกใน "บันทึกการใช้งาน" (จำนวนผู้รับแยกตามบทบาท ไม่บันทึกอีเมล)
   ถ้าส่งไม่สำเร็จ (เช่น โควตาอีเมลรายวันเต็ม) บันทึกเป็น FAILED แทนการเงียบหายใน Logger

**ข้อควรรู้**
- โควตาอีเมลของ Apps Script บัญชี Google Workspace ประมาณ 1,500 ผู้รับ/วัน (นับต่อผู้รับ)
- ผู้รับต้องมีสถานะใช้งาน (active) ในทะเบียนผู้ใช้
- แนะนำทดสอบจริง 1 ครั้ง: สร้างเรื่องทดสอบระดับ 4 แล้วตรวจกล่องอีเมลอธิการบดี/รองอธิการบดี และบันทึกการใช้งาน

# รุ่น 2.8.13 — แจ้งเตือนมาตรการเกินกำหนด และสิทธิ์ปิดมาตรการ
